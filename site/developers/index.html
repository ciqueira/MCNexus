SDK & Integration

Native C/C++ SDK.

The NexKeyRuntime delivers local Ed25519 cryptographic verification on the user's machine with a stable C ABI. On the host render thread (OFX), the license decision is a single atomic memory read, with zero locks, zero syscalls, and zero network calls.

Architecture

Integration options.

End-to-end circuit operation, coupling the native MCNexus app to an existing store or license issuer, or embedding only the C/C++ SDK inside a standalone product.

Profile A + Commerce

Full Circuit.

For new free or commercial plugin releases. The macOS and Windows MCNexus app activates the license, downloads the binary, installs, updates in 1 click, and rolls back on the workstation.

Sales run directly on the developer's Stripe account (0% commission). The plugin embeds NexKeyRuntime only to verify the local receipt. On the free Community plan, the SDK is optional.

Profile A + Existing Stack

Coupled to an Existing Stack.

For operations already selling or issuing licenses externally. Preserves an existing Cryptlex account (integrated today) or connects to external stores and storage (Lemon Squeezy*, Shopify*, Cloudflare R2*, AWS S3*, GitLab Releases* on the roadmap, prioritized with partners).

The existing checkout and key issuer remain in place while the native MCNexus app eliminates manual file extraction and operating system installation blocks.

Profile B Standalone

NexKeyRuntime SDK Only.

For native software with its own installer outside OFX. The product links the C/C++14 SDK and activates, synchronizes, and deactivates the license directly, with no MCNexus desktop app in the loop.

Includes offline and file-based air-gap activation, update/notice polling, and automatic GUI versus headless process detection for servers and render farms.

Code · NexKeyRuntime C/C++14 SDK

The lifecycle in snippets.

Real API from the public NexKeyRuntime C header, not pseudocode. On the render thread, the decision is a single atomic read with zero network or disk I/O.

/* 1. Initialize and load the local receipt. */
NexKeyRuntimeLicenseHandle *license = nexkeyruntime_license_create();
nexkeyruntime_license_set_product_data(license, PRODUCT_DATA);
nexkeyruntime_license_set_tenant_id(license, "tenant-id");
nexkeyruntime_license_set_variant(license, "download:entitlement");
nexkeyruntime_license_load_local(license);

PRODUCT_DATA is a signed public blob issued for the tenant (public keyring + base URL, no private secret). Safe to commit in public repositories.

/* 2. Decide on the render thread.
      No lock, no allocation, no syscall, no network. */
if (nexkeyruntime_license_render_decision(license)
        == NEXKEYRUNTIME_RENDER_ALLOW) {
    render_frame(frame);
}

Safe inside real-time OFX render callbacks. Cryptographic verification and background renewal happen off the critical path.

/* 3. Read edition (Demo/Trial/Full) off the critical path. */
NexKeyRuntimeLicenseSnapshot snapshot = { sizeof(snapshot) };
if (nexkeyruntime_license_get_snapshot(license, &snapshot)
        == NEXKEYRUNTIME_OK) {
    bool is_demo = (snapshot.edition_enum
        == NEXKEYRUNTIME_EDITION_DEMO);
    set_watermark_enabled(is_demo);
}

When a Demo key upgrades to Full after purchase, edition_enum switches to NEXKEYRUNTIME_EDITION_FULL on the next sync.

Platform Capabilities

What is built into the core.

Every item below operates in production and links to its corresponding technical specification.

  • Clean host Inspector & .drp / PowerGrade safety: because activation happens in the MCNexus desktop app rather than inside OFX plugin parameters, customer emails and license keys are never saved inside shared DaVinci Resolve .drp projects or PowerGrades, and no HTTP calls ever block the host UI thread. User guide →
  • Node-locked activation & self-service transfer: an Ed25519 certificate signed by a tenant-scoped key and bound to the machine fingerprint, with configurable seat limits and 1-click self-service deactivation so end users can transfer machines without opening support tickets. Supports OpenKey (native) and Cryptlex. Distribution models →
  • Offline window & air-gap files: certificates carry two independent timestamps: syncAfter (when background renewal starts) and offlineValidUntil (the hard limit the SDK enforces). The offline window always covers multiple renewal attempts, so a transient outage never denies a license. Isolated workstations activate via .req / .lic files. Continuity & offline →
  • NexKeyRuntime 1.0 (stable C ABI): native C/C++14 library for macOS universal (arm64 + x86_64) and Windows x64. Public contract (C header, JSON Schemas, docs and examples) under Apache-2.0; binary ABI guaranteed across 1.x. Client SDK →
  • Protected distribution & 1-click rollback: short-lived signed download tokens proxy every release with streaming SHA256 verification. The client app never receives the raw storage URL. End users can update in 1 click or roll back to a previously published version. Security and distribution →
  • Commerce & duplicate-safe fulfillment: sales run directly on the developer's own Stripe account (0% platform commission). Nexus records the order, payment event and accepted legal terms version, and deduplicates webhook retries so a single order never issues two licenses. Nexus Commerce flow →
  • Key ownership & 4-slot keyring: the tenant keyring holds up to four public keys so rotating a signing key never invalidates already-installed plugins. On Pro and SDK plans, a developer-generated offline recovery key can be registered without its private half ever touching the server. Key continuity →
  • In-product notices: critical, recommended and info notices with localized copy and targeting by host, version range, OS and architecture. Plain text only, with no HTML, arbitrary Markdown or scripts. Updates and notices ↗

Editions & Channels

License editions and release channels.

OpenKey natively supports four license editions and separates stable production binaries from beta prereleases at the backend gate.

Edition 01 · Closed Testing

Beta

Isolated beta (prerelease) channel for invited testers. Production licenses (Full, Trial, Demo) strictly receive stable releases, and Beta keys are blocked from checkout issuance by security policy.

Edition 02 · Unlimited Evaluation

Demo

Users claim a free evaluation key via Get Key and install through MCNexus with no expiration date. The plugin reads NEXKEYRUNTIME_EDITION_DEMO from the SDK snapshot and applies a watermark or feature limit.

Edition 03 · Time-Boxed Evaluation

Trial

Full functionality with an automatic day countdown (trial_days) that starts on the first machine activation. Once expired, the local certificate transitions cleanly without locking up the host application.

Edition 04 · In-Place Upgrade

Full

When a buyer completes payment at checkout using the same verified email from a Demo or Trial, Nexus automatically promotes the existing key to Full (upgradeEdition), unlocking the already-installed plugin without reinstalling or breaking .drp timelines.
