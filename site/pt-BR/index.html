SDK NexKeyRuntime

Verificação offline sem travar o playback.

A verificação opera 100% offline. Na thread de render, a decisão de licença é uma leitura atômica em memória: sem locks, sem rede e sem I/O de disco. Renovação e validação criptográfica ocorrem fora do caminho de renderização. C/C++14 com ABI C estável.

Guia para desenvolvedores → 
#include <nexkeyruntime/nexkeyruntime.h>

NexKeyRuntimeLicenseHandle *license = nexkeyruntime_license_create();
nexkeyruntime_license_set_product_data(license, PRODUCT_DATA);
nexkeyruntime_license_set_tenant_id(license, "tenant-id");
nexkeyruntime_license_load_local(license);

/* Na thread de render: uma leitura atômica.
     Sem lock, sem alocação, sem syscall. */
if (nexkeyruntime_license_render_decision(license)
        == NEXKEYRUNTIME_RENDER_ALLOW) {
    render(frame);
}

Arquitetura modular

Conectores independentes.

Cada camada opera sob contratos explícitos, permitindo rodar com o circuito nativo em produção hoje e conectar provedores externos conforme os adaptadores do roadmap forem liberados.

  • 1. Verificação de licença: integração da biblioteca leve NexKeyRuntime em C/C++. Validação de certificados criptográficos node-locked 100% offline com suporte a air-gap. (Alternativa: Cryptlex).
  • 2. Publicação de releases: pacotes hospedados em GitHub Releases públicos ou privados com tokens assinados de download e verificação de integridade SHA256. (Cloudflare R2* / AWS S3* no roadmap).
  • 3. Checkout e fulfillment: cobrança via Stripe nativo na conta do desenvolvedor (0% de comissão). Emissão e entrega imediata da licença (Beta, Demo, Trial ou Full) no ato da compra, com envio por e-mail transacional e fulfillment automatizado.
  • 4. Entrega nativa no desktop: instalação no diretório nativo de OFX com 1 clique pelo aplicativo MCNexus no macOS e Windows, com atualizações e rollback imediato de versão.

Continuidade

O que acontece se o Nexus parar.

Um produto licenciado não pede permissão a um servidor para rodar. Se o backend do Nexus for interrompido, as máquinas já ativadas continuam funcionando durante toda a janela offline (30 dias por padrão).

A chave de recuperação sob custódia do desenvolvedor permite emitir certificados de emergência sem depender da infraestrutura do Nexus; a exportação de dados para encerramento planejado é um trabalho planejado.

Integrações projeto a projeto.
