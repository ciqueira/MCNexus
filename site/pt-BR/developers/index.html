SDK & Integração

SDK nativa em C/C++.

O NexKeyRuntime entrega verificação criptográfica Ed25519 na máquina do usuário com ABI C estável. Na thread de render do host (OFX), a decisão de licença é uma leitura atômica em memória, com zero lock, zero syscall e sem chamadas de rede.

Arquitetura

Opções de integração.

Operação pelo circuito conectado de ponta a ponta, acoplamento do aplicativo nativo MCNexus a uma loja ou emissor de licenças existente, ou uso exclusivo da SDK C/C++ em software standalone.

Perfil A + Commerce

Circuito Completo.

Para lançamentos de plugins gratuitos ou comerciais. O aplicativo MCNexus para macOS e Windows ativa a licença, baixa o binário, instala, atualiza em 1 clique e executa rollback na estação de trabalho.

As vendas operam diretamente na conta Stripe do desenvolvedor (0% de comissão). O plugin embarca o NexKeyRuntime apenas para ler o recibo local. No plano Comunidade gratuito, a SDK é opcional.

Acoplado ao Stack Atual.

O checkout e o emissor de chaves atuais são preservados, enquanto o aplicativo MCNexus elimina o envio manual de arquivos e os bloqueios de sistema operacional.

Perfil B Standalone

Apenas a SDK NexKeyRuntime.

Para software nativo com instalador próprio fora de OFX. O próprio produto linka a SDK C/C++14 e ativa, sincroniza e desativa a licença diretamente, sem o aplicativo MCNexus no caminho.

Inclui ativação offline e air-gap por arquivo, consulta de updates/avisos e detecção automática de processo com interface gráfica (GUI) versus headless para servidores e render farms.

Código · SDK C/C++14 NexKeyRuntime

O ciclo em trechos.

API real do header público do NexKeyRuntime, não pseudocódigo. Na thread de render, a decisão é uma leitura atômica sem rede e sem I/O de disco.

/* 1. Inicializar e carregar o recibo local. */
NexKeyRuntimeLicenseHandle *license = nexkeyruntime_license_create();
nexkeyruntime_license_set_product_data(license, PRODUCT_DATA);
nexkeyruntime_license_set_tenant_id(license, "tenant-id");
nexkeyruntime_license_set_variant(license, "download:entitlement");
nexkeyruntime_license_load_local(license);

O PRODUCT_DATA é um blob público assinado emitido para o tenant (keyring público + URL base, sem chave privada). Seguro para repositórios públicos.

/* 2. Decidir na thread de render.
      Sem lock, sem alocação, sem syscall, sem rede. */
if (nexkeyruntime_license_render_decision(license)
        == NEXKEYRUNTIME_RENDER_ALLOW) {
    render_frame(frame);
}

Chamada segura dentro do callback de render OFX em tempo real. A verificação criptográfica e a renovação ocorrem fora do caminho crítico.

/* 3. Ler a edição (Demo/Trial/Full) fora do caminho crítico. */
NexKeyRuntimeLicenseSnapshot snapshot = { sizeof(snapshot) };
if (nexkeyruntime_license_get_snapshot(license, &snapshot)
        == NEXKEYRUNTIME_OK) {
    bool is_demo = (snapshot.edition_enum
        == NEXKEYRUNTIME_EDITION_DEMO);
    set_watermark_enabled(is_demo);
}

Quando uma chave Demo faz upgrade para Full após a compra, edition_enum passa para NEXKEYRUNTIME_EDITION_FULL na sincronização seguinte.

Capacidades da Plataforma

O que está incluído no núcleo.

Cada recurso abaixo opera em produção e referencia a especificação técnica correspondente na documentação.

  • Inspector limpo no host e proteção de .drp / PowerGrades: como a ativação ocorre no aplicativo MCNexus (fora dos parâmetros OFX do plugin), o e-mail e a chave do comprador nunca ficam gravados dentro de projetos .drp ou PowerGrades compartilhados, e nenhuma chamada HTTP bloqueia a UI thread do host. Guia de operação →
  • Ativação node-lock e transferência self-service: certificado Ed25519 assinado por chave com escopo de tenant e vinculado ao fingerprint da máquina, com limite configurável de vagas e desativação em 1 clique em autoatendimento para transferência de estação sem chamado de suporte. Suporta OpenKey (nativo) e Cryptlex. Modelos de distribuição →
  • Janela offline e arquivos air-gap: o certificado carrega dois prazos independentes: syncAfter (início da tentativa de renovação em segundo plano) e offlineValidUntil (limite rígido aplicado pela SDK). A janela offline cobre múltiplas tentativas de renovação, impedindo que falhas transitórias de rede neguem uma licença válida. Estações isoladas ativam por arquivos .req / .lic. Continuidade e offline →
  • NexKeyRuntime 1.0 (ABI C estável): biblioteca nativa em C/C++14 para macOS universal (arm64 + x86_64) e Windows x64. Contrato público (header C, JSON Schemas, documentação e exemplos) sob Apache-2.0; compatibilidade binária garantida em toda a série 1.x. SDK de cliente →
  • Distribuição protegida e rollback em 1 clique: tokens assinados de curta duração fazem proxy de cada download com verificação SHA256 em streaming. O aplicativo nunca recebe a URL real do storage. Permite atualização em 1 clique ou retorno imediato a versões publicadas anteriormente. Segurança e distribuição →
  • Commerce e fulfillment à prova de duplicidade: as vendas correm diretamente na conta Stripe do desenvolvedor (0% de comissão da plataforma). O Nexus registra o pedido, o evento de pagamento e a versão dos termos aceita pelo comprador, deduplicando retentativas de webhook para evitar emissões em duplicidade. Fluxo Nexus Commerce →
  • Posse de chave e keyring de 4 slots: o keyring do tenant comporta até quatro chaves públicas para que a rotação de chave não invalide instalações existentes. Nos planos Pro e SDK, uma chave de recuperação offline gerada pelo desenvolvedor pode ser registrada sem que a metade privada passe pelo servidor. Continuidade de chave →
  • Avisos in-app (Notices): severidades critical, recommended e info com texto localizado e segmentação por host, faixa de versão, sistema operacional e arquitetura. Conteúdo estritamente em texto puro, sem HTML, Markdown arbitrário ou scripts. Updates e avisos ↗

Edições e Canais

Edições de licença e canais de release.

O OpenKey suporta nativamente quatro edições de licença e separa binários de produção (canal stable) de versões de teste (canal beta) diretamente no gate do backend.

Edição 01 · Testes Fechados

Beta

Canal beta (prerelease) isolado para testers convidados. Licenças de produção (Full, Trial e Demo) recebem estritamente releases do canal stable, e chaves Beta são bloqueadas contra emissão no checkout por regra de segurança.

Edição 02 · Avaliação Sem Prazo

Demo

O usuário obtém uma chave gratuita em Get Key e instala pelo MCNexus sem data de expiração. O plugin lê NEXKEYRUNTIME_EDITION_DEMO no snapshot da SDK e aplica marca d'água ou limite de resolução/função.

Edição 03 · Avaliação Por Dias

Trial

Funcionalidade completa com contagem regressiva de dias (trial_days) iniciada automaticamente na primeira ativação na máquina. Ao expirar, o certificado local muda de estado sem travar o host.

Edição 04 · Upgrade Na Mesma Chave

Full

Quando o comprador conclui o pagamento no checkout com o mesmo e-mail verificado da Demo ou Trial, o Nexus promove automaticamente a chave existente para Full (upgradeEdition), destravando o plugin já instalado sem reinstalar e sem quebrar projetos .drp.
