Nexus · Licensing infrastructure

Licensing, distribution and updates for native software that runs offline.

The activation certificate is verified on the end user's machine, against a keyring compiled into the product binary. The network renews a certificate; it never grants one that is already valid. Backend, a native C/C++ SDK and a client app for macOS and Windows.

NexKeyRuntime SDK

License decision on the render thread.

The decision is a single atomic read: no lock, allocation, syscall, network, file I/O or JSON parsing. License resolution happens off the critical path, and the certificate is verified locally. The SDK is C/C++14 with a stable C ABI.

Integration → 
#include <nexkeyruntime/nexkeyruntime.h>

NexKeyRuntimeLicenseHandle *license = nexkeyruntime_license_create();
nexkeyruntime_license_set_product_data(license, PRODUCT_DATA);
nexkeyruntime_license_set_tenant_id(license, "tenant-id");
nexkeyruntime_license_load_local(license);

/* On the render thread: a single atomic read.
     No lock, no allocation, no syscall. */
if (nexkeyruntime_license_render_decision(license)
        == NEXKEYRUNTIME_RENDER_ALLOW) {
    render(frame);
}

Platform

What the platform does.

Backend, native SDK and client app, for commercial or open-source native software. Integrations are reviewed and configured per project.

  • Node-locked activation: an Ed25519 certificate bound to the machine fingerprint, a seat limit per license, and self-service deactivation.
  • Offline and air-gap: local verification against a public keyring compiled into the product — the network renews a certificate, it never grants one already valid. Offline window configurable per license. With no network at all, activation and deactivation through exported files.
  • NexKeyRuntime: a native SDK in C/C++14 with a stable C ABI, macOS and Windows. A product with its own installer links it and activates, synchronizes and deactivates with no client app in the loop.
  • MCNexus client: a macOS and Windows app that activates, installs, updates and rolls back on the workstation — for OFX plugins, with no client of the developer's own.
  • Key ownership and continuity: an Ed25519 signing key per tenant that can be the developer's own, rotation that does not invalidate installed copies, and a recovery key that issues certificates with no Nexus in the loop.
  • Distribution and rollback: download through short-lived signed tokens, per-platform packages, version discovery, and reinstalling a previously published release.
  • Editions and entitlements: beta, demo, trial and full, time-limited trials, per-asset entitlements, scoped so one machine cannot hold two seats of the same entitlement.
  • Commerce and fulfillment: Stripe on the developer's own account, offer catalog, idempotent fulfillment, one-time key reveal, transactional email, and legal acceptance recorded per order.
  • In-product notices: severity levels, localized content, targeting by host, version, platform and architecture, dismissible and postponable, over the update channel.

Pricing

Free for free software.

The boundary is whether the end user is charged. Activation volume does not enter the calculation in any plan — no cap, no per-unit price.

Community

Free

For a product that is not charged to the end user. Automatic entry, no application and no approval.

  • Installation, updates and rollback through MCNexus

MCNexus app

App for installing plugins.

MCNexus centralizes license activation, OFX plugin installation, updates, and access to available previous versions.

  • Automatic installation: downloads and installs the OFX files into the directory defined by the operating system.
  • Updates and rollback: identifies published versions and installs an update or returns to an available previous version.
  • Independent actions: activating or deactivating a license, removing the local key, and removing the plugin are separate operations.
  • License transfer: when the previous installation is reachable, the license can be deactivated before a new activation.

Continuity

What happens if Nexus stops.

A licensed product does not ask a server for permission to run, so a backend interruption is not a license denial: machines already activated keep working for the whole offline window. The recovery key is generated by the developer and its private half never reaches Nexus infrastructure: already-installed copies accept certificates issued by that key, with no server in the loop.

The document also records what an interruption does stop and what does not exist yet.
